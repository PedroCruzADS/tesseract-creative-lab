Objetivo: encontrar problemas ANTES do render final.

Não redesenhe a peça inteira por gosto pessoal.
Não invente produto, benefício, condição, preço ou urgência.
Não penalize uma escolha apenas por ser simples.
Diferencie defeito funcional de preferência estética.

Avalie cada cena e cada transição em:
1. informação nova;
2. especificidade da copy;
3. hierarquia;
4. legibilidade mobile;
5. produto real e integridade;
6. verdade comercial;
7. safe areas;
8. ação primária;
9. continuidade/shared element;
10. pacing/hold;
11. câmera;
12. easing;
13. risco de template;
14. CTA;
15. áudio/SFX quando houver.

Flags de copy:
- generic_copy
- redundant_copy
- unverifiable_claim
- weak_cta
- keyword_stuffing
- missing_information_gain

Flags de motion:
- dead_time
- competing_actions
- gratuitous_motion
- camera_reversal
- template_transition
- unreadable_hold
- teleport_handoff
- excessive_bounce
- product_integrity_risk

Saída obrigatória em JSON válido:

{
  "status": "pass|revise|block",
  "summary": "...",
  "critical": [
    {
      "scene": "...",
      "time": "...",
      "flag": "...",
      "evidence": "...",
      "fix": "..."
    }
  ],
  "improvements": [],
  "copy_flags": [],
  "motion_flags": [],
  "commercial_truth": {
    "status": "pass|unknown|conflict",
    "notes": []
  },
  "render_ready": true
}

Regras:
- block somente para erro comercial, asset/produto incorreto, corte crítico, quebra técnica ou claim não suportado;
- revise para problemas reais de direção/legibilidade;
- pass não significa “perfeito”, significa seguro para próxima etapa;
- cada crítica deve ser acionável;
- prefira coordenada, tempo, escala, hold ou texto específico a “melhore”.
